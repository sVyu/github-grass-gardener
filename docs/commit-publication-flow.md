# 커밋 발행 흐름

1. 사용자가 초안의 날짜·개수·메시지·이메일·시간대를 정하고 미리보기를 요청한다.
2. 앱이 저장소 상태와 이메일을 검증하고 기본 브랜치 HEAD를 읽어 계획에 고정한다.
3. 사용자가 명시적으로 `Publish`를 누르면 HEAD를 다시 읽는다. 불일치하면 **아무 파일도 쓰지 않고** 중단한다.
4. 각 항목마다 현재 HEAD를 재검사하고, `.grass-gardener/activity.jsonl`의 다음 행을 포함한 Blob → Tree → Commit을 생성한다. Git commit의 author와 committer에 동일한 계정 이메일과 선택 날짜의 ISO 8601 시각을 설정한다.
5. 브랜치 ref를 `force: false`로 갱신한다. 응답이 불확실하면 HEAD를 다시 읽어 실제 적용 여부를 판단한다. 성공한 SHA를 즉시 결과에 기록하고 다음 항목으로 이동한다.

HEAD 충돌·권한 오류·속도 제한·네트워크 오류가 나면 추가 발행을 멈추고 성공·실패·건너뛴 항목을 구분해 표시합니다. 이미 성공한 커밋은 되돌리지 않습니다. 사용자는 저장소 상태와 기여 캘린더를 새로 조회한 뒤 남은 항목으로 새 계획을 만들 수 있습니다. 같은 배치 ID의 활동 로그 항목은 중복 발행 방지에 사용됩니다.

이 흐름은 append-only이며 기존 커밋의 날짜나 SHA를 수정하지 않습니다. GitHub 기여 집계는 별도 확인이 필요합니다.
