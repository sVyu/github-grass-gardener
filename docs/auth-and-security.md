# 인증과 보안

웹 MVP는 사용자가 입력한 GitHub PAT로 직접 GitHub API를 호출합니다. 토큰은 `BrowserCredentialStore`의 메모리에만 보관하며, URL·로그·브라우저 영구 저장소·리포지토리 파일에 기록하지 않습니다. 연결 해제 및 새로고침 시 토큰이 사라지는 것은 의도된 동작입니다. XSS나 악성 브라우저 확장 프로그램의 실시간 메모리 접근까지 차단하는 보안 경계는 아니므로, 신뢰할 수 있는 로컬 실행 환경에서 사용해야 합니다.

토큰에는 대상 저장소의 콘텐츠 쓰기 권한이 필요합니다. 새 저장소 생성과 확인된 이메일 조회에는 추가 권한이 필요할 수 있으며, Fine-grained PAT는 저장소 생성이 거부될 수 있습니다. 생성 오류 시 기존 저장소 선택 경로를 유지합니다. 이메일 API가 403을 반환하면 사용자 ID 기반 GitHub `noreply` 주소만 선택지로 제공합니다.

발행 전에는 저장소 쓰기 권한, 보관·비활성화 여부, 기본 브랜치 및 보호 상태, 원격 HEAD, 이메일 선택을 확인합니다. 단, 사전 검사 후에도 권한·브랜치 상태가 바뀔 수 있으므로 GitHub의 최종 API 응답과 `force: false` 갱신 실패를 별도로 처리합니다. 사용자에게 원시 토큰이나 응답 본문을 노출하지 않고 상태별 안내 문구를 표시합니다.

공개 서비스로 전환할 때는 PAT 직접 입력 대신 GitHub App 또는 OAuth/BFF 인증과 서버 측 자격증명 보관을 재설계해야 합니다.
